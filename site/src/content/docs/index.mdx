## The whole idea in sixty seconds

An exobrain is a **git repository of markdown files** that your coding agent loads as context at the start of every session.

Two kinds of content live in it. **Knowledge** is durable — how your stack is set up, which conventions your projects follow, what you decided and why. **Workspaces** are time-bound — an investigation, a migration, a piece of work with a beginning and an end.

**Scopes** decide what loads. A rule that belongs to everyone lives at the top; a rule that only applies to you, or only on one machine, lives further down. Your agent inherits the whole chain, innermost wins.

That's it. No database, no service, no daemon, no account. Files you can read, in a repo you own, that your agent reads too.

<CardGrid stagger>
  <Card title="Any agent" icon="puzzle">
    Universal context lives in `AGENTS.md`. Per-agent quirks live in `CLAUDE.md`, `CODEX.md`, or `OPENCLAW.md` sidecars. Switching agents doesn't mean rewriting anything.
  </Card>
  <Card title="Yours outright" icon="approve-check">
    You don't fork this repo and you never merge from it. An agent reads the concept and builds *your* exobrain, with names and structure that fit you. It has no upstream.
  </Card>
  <Card title="Readable" icon="document">
    Every fact is a line of markdown in a git history. When your agent gets something wrong you can see exactly which line taught it that, and fix it.
  </Card>
  <Card title="Scales down" icon="setting">
    A useful exobrain is one `AGENTS.md` and one knowledge file. The rest exists when you need it and stays out of the way when you don't.
  </Card>
</CardGrid>
