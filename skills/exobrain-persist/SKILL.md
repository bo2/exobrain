# Persist

Land a completed logical change on the default branch in one shot, through a pull request. This is the **default** flow: `AGENTS.md` § Git workflow grants standing authorization to run it without being asked once a logical change is genuinely done — when more edits or a correction are likely (mid-task, or the user is still iterating), hold and confirm first. The user can also invoke it by name. Follow that git workflow throughout.

1. **Get onto a branch.** Normally you're already in the worktree you started the work in (`AGENTS.md` § Git workflow — worktree-first), so this is a no-op. Recovery only — if work wrongly began in-place on the default branch, move it to a branch first (`git stash -u` → `scripts/create-worktree.sh <branch>` → `cd` into it → `git stash pop`); worktree-first means this shouldn't happen.
2. **Commit** — one commit per logical change, imperative mood. Leaving the work uncommitted and passing `-m` to the script in step 4 is equivalent.
3. **Behaviorally verify shared-machinery changes.** When this change touches machinery that shapes how other agents behave — root `scripts/`, the registries (`skills.json` / `scopes.json` / `skills.schema.json`), a root `skills/` skill, or a global-scope spec (`AGENTS.md` and the per-agent sidecars) — verify it before it lands; pure docs (`knowledge/`, `tools/`, `workspaces/`) and person/host-scope changes are exempt. The script runs the deterministic unit suite (`skills/exobrain-tests/unit/run.sh`) itself. The agent-judged half is yours: run the behavioral suite (the `exobrain-tests` skill) over the cases this change could move — it snapshots HEAD, so the commit in step 2 is what gets tested. Fix any case below threshold, `git commit --amend` the unpushed commit, then re-run. For a change *meant to alter behavior* (a reworded rule, a new or edited skill), also run `exobrain-ab` to confirm it actually moves behavior — a spec edit that changes nothing isn't worth landing. You judge which cases are relevant and whether the change is behavior-altering. The script refuses to land such a diff until `--machinery-verified` asserts that this happened; its refusal names the flag.
4. **Land** — from inside the worktree:

   ```bash
   scripts/persist.sh [-m "<commit message>"] [--timeline "<one-line summary>"] [--machinery-verified]
   ```

   The script does the rest in order, each step skipped when already done, so re-running after an interruption resumes rather than repeats: appends a row (`| date | author | summary |`) to the `TIMELINE.md` of every workspace or knowledge domain touched whose `README.md` frontmatter carries `timeline: true` (creating the file if absent; `--timeline` sets the summary, else the commit subject — see [`knowledge/exobrain/domains.md`](../../knowledge/exobrain/domains.md) → "Timeline tracking") → commits anything still uncommitted → `scripts/validate-exobrain.sh` → `scripts/authoring-review.sh` (the LLM judgment layer over changed spec/domain files; skippable with `EXOBRAIN_SKIP_AUTHORING_REVIEW=1`) → pushes the branch → opens the PR (title from the branch's first commit unless `--title` says otherwise; body from the commits) → squash-merges it (a merge refused for a conflict merges the default branch into the branch and retries once) → fast-forwards the main checkout → removes the worktree and deletes the branch locally and on the remote. Without a remote, push through merge collapse into a fast-forward of the local default branch.

   A failed step stops the script with the branch keeping every step already made: fix what it named (a validator violation, an authoring finding, a conflict left in the worktree), amend the still-unpushed commit if the commit is what changed, and re-run. `--dry-run` prints the plan.
5. **Continuing the same work?** Create a fresh worktree off the updated default branch before further edits. Ask if the intent isn't clear.

**Landing later, or from a chat turn.** The script is safe to run detached: it claims the worktree first, so a run that dies leaves a claim the sweep picks up (a claim made with `--machinery-verified` carries the assertion). `scripts/persist.sh --sweep` (from any checkout of the repo) lands every claimed worktree and every clean worktree that is ahead of the default branch and untouched for an hour, and leaves dirty worktrees alone; a host that runs chat sessions schedules it in its `crons.json`. How a runtime detaches the land is that runtime's sidecar's business (root `OPENCLAW.md` § Persisting from a chat turn).
